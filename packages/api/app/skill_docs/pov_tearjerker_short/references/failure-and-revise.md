# 改稿与失败处理 · 第一视角催泪短片

与 SKILL 冲突时以 SKILL 为准。原则：**改哪里动哪里**；不要整段推倒重来，除非用户明确要求。

## 1. 改方案（尚未出板或只要改文字）

| 用户意图 | 动作 |
|----------|------|
| 改情感物 / 场景 / 镜数 / 时长 | 更新草案表 → 再 `ask_user` 是否出板 |
| 「先不出板」 | 停在文字方案；禁止 storyboard |
| 「重写一版完全不同」 | 新草案表 + 新三件套说明 → 再 ask |

## 2. 改故事板（已出板）

| 用户意图 | 动作 |
|----------|------|
| 「再出一张板 / 重新生成故事板」 | 允许再次 `storyboard`；用更新后的 userPrompt |
| 「只要改第 3 格气氛」 | 优先改草案 + 重出板；或说明整板会重绘 |
| 「板可以，不改了」 | 进入搭镜 / 出片确认 |

不要在用户未要求时自动重出第二张板。

## 3. 改某一视频镜头

| 用户意图 | 动作 |
|----------|------|
| 「第 2 镜重做」 | 只对该镜改参 → 确认后只 regenerate；其后镜若依赖尾帧，可说明「重做后会重新用尾帧接下镜」 |
| 「台词再多 / 再少」 | 改剧本 → 再 ask 定镜 |
| 「再加几镜 / 做长视频」 | 加节拍拆镜 → 更新 N → 再 ask |
| 「这一镜换故事 B」 | 锁定备选 → 若已出板则问是否重出板 |
| 「第 3 镜加长到 8 秒」 | 改 duration（≤12）→ 确认后只重生该镜 |
| 「整段重来」 | 确认后：可清批次或新 batchId，再同批生成 |

未确认出片前改镜：只改节点参数，不 generate。

## 4. 生成失败

| 情况 | 动作 |
|------|------|
| 单镜失败 | 对话说明哪一镜失败；问是否重试该镜；不要无故重跑全部 |
| 多镜失败 | 列出失败段号；只重试失败段；**禁止**重挂整板到多镜并行 |
| 故事板失败 | 说明原因（若有）；问是否换描述重试出板 |
| 上游排队/限流 | 用人话说明稍后再试；不要暴露内部错误码堆栈 |

## 5. 用户中途换主题

例如从「父爱」改成「师生」：

1. 明确告知「主题变了，草案会重做」。  
2. 按新主题走收题→方案→ask 出板。  
3. 旧板是否保留：问一句即可；默认不自动删画布节点，除非用户要求清场。

## 6. 禁止

- 失败后静默再跑整批导致双倍扣费感知  
- 用户说改一镜却重出整张故事板（除非板与该镜强绑定且用户同意）  
- **禁止**把整板同时连多个 video 并行 generate（参考污染）
- 用内部字段名解释失败原因
